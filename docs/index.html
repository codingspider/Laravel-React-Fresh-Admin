Server Requirements

Ensure your server meets these requirements before installation.

Backend

  • PHP 8.2 or higher
  • Laravel 12.x
  • MySQL 8.0+ / MariaDB 10.6+
  • Composer 2.x
  • Node.js 20+ & npm
  • PHP Extensions: pdo_mysql, mbstring, openssl, xml, ctype, curl, gd, zip, bcmath, fileinfo, tokenizer, json

Frontend

  • React 19.x
  • Chakra UI 2.x
  • Vite 7.x
  • React Router DOM 7.x
  • React Hook Form 7.x
  • Tailwind CSS 4.x (dev)
Note: Redis is optional but recommended for caching. The application will work with file-based caching.

Installation

Follow these steps to get the application running on your server.

1

Extract & Upload

Extract the downloaded zip file and upload all files to your server's public directory (or subdirectory).

# Upload to your server
scp -r ./restaurant user@your-server:/var/www/html/restaurant
2

Install PHP Dependencies

Navigate to the project root and run Composer install.

cd restaurant
composer install
3

Configure Environment

Copy the example environment file and configure your database and application settings.

# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env

Edit .env and set your database credentials, APP_URL, and FRONTEND_URL.

4

Generate App Key & Run Migrations

Generate the encryption key and create all database tables with seed data.

php artisan key:generate
php artisan migrate --seed
This creates default users (Super Admin, Admin, Restaurant Owner) with password 123456789.
5

Install Frontend & Build

Install Node dependencies and build the React frontend.

npm install
npm run build
6

Start the Server

Launch the Laravel development server.

php artisan serve

Visit http://localhost:8000 in your browser.

!

Optional: Load Demo Data

Seed sample menu items, tables, and categories for testing.

php artisan db:seed --class=Database\Seeders\DemoSeeder

Database Migration & Seeding

GET /install/progress

After environment configuration, the installer runs database migrations and seeds in the background.

What Runs Automatically

  • php artisan migrate --force — creates all database tables
  • php artisan db:seed --force --class=UserSeeder — seeds roles & permissions

Progress Tracking:

The page polls the server every 2 seconds. When complete, it automatically proceeds to Step 4. If an error occurs, an alert is shown with the error message.

4

Admin Account & Restaurant Setup

GET /install/admin

Create your super admin account and default restaurant. This is the final step.

Form Fields

Field Validation Required
Admin Name string, max 255 Yes
Admin Email valid email, unique in users table Yes
Password min 8 characters Yes
Confirm Password must match password Yes

What Gets Created

  • Super Admin user with the provided name, email, and hashed password
  • Default Restaurant named "{Admin Name}'s Restaurant" with USD currency, UTC timezone
  • Main Branch created under the default restaurant
  • super_admin role assigned to the user (via Spatie Permission)
  • storage/installed marker file written
  • SESSION_DRIVER updated from file to database

Installation Complete!

You'll be redirected to the Home page. Use the admin credentials you just created to sign in.

Home URL:

https://yourdomain.com
Important: The storage/installed file acts as a lock. Once installed, the /install route becomes inaccessible. To reinstall, delete the storage/installed file and drop all database tables.

Roles & Permissions

Granular access control using Spatie Laravel Permission.

Default Roles

Role Description
super_admin Full access to all modules and settings
admin Full access (kept for extensibility)
restaurant_owner Full access to own restaurant data

Permission Pattern

Permissions follow the pattern: {action}_{entity}

view_restaurants create_menu_items update_reservations delete_floors process_sale manage_kitchen_orders

Actions: view, create, update, delete. Total: 120+ permissions seeded via UserSeeder.

Frontend Permission Check

import { usePermission } from '../../context/PermissionContext';

const { can, hasRole } = usePermission();

// Permission check
{`{can('create_restaurants') && }`}

// Role check
{`{hasRole('super_admin') && }`}

Security

Built-in security features to protect your application and data.

HTTP-Only Cookie Auth

No localStorage tokens. Sanctum stateful SPA authentication with secure cookies.

CSRF Protection

Cross-site request forgery protection on all forms and state-changing requests.

Password Hashing

Bcrypt with 12 rounds. Never stored in plain text.

Rate Limiting

Request throttling (120 requests/minute) on all API routes.

Activity Logging

All write operations are logged with user, IP, and request details.

Data Isolation

Restaurant-scoped middleware ensures each restaurant only sees its own data.

FAQ

Frequently asked questions.

What are the default login credentials?

Super Admin: superadmin@gmail.com / 123456789

Admin: admin@gmail.com / 123456789

Restaurant Owner: owner@gmail.com / 123456789

Can I disable modules I don't need?
Yes. Edit modules_statuses.json in the project root to enable or disable any module. Disabled modules won't load routes, migrations, or appear in the sidebar.
How do I add a new language?

Backend: Create a new locale folder under Modules/{Module}/lang/{locale}/ and add translated strings.

Frontend: Add a new translation file in the i18n configuration and update the language switcher component.

Is this application production-ready?
Yes. The application is built with production-grade security (CSRF, rate limiting, input validation, data isolation), follows Laravel best practices, uses PSR-12 coding standards, and includes activity logging and error handling. It is designed for CodeCanyon commercial distribution.
Can I use this as a SaaS platform?
Absolutely. The application includes a complete SaaS infrastructure with subscription plans, feature packages, module access control, and a super admin dashboard for managing all tenants. Each restaurant operates in its own isolated data scope.
What payment methods are supported?
Cash, Card, Cheque, Bank Transfer, Bkash, Nagad, Rocket, USDT, and Other. Multiple payment types can be used per order for split payments.
